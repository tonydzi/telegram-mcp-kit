# Готовые промпты

Заполните только несекретные placeholders. Вставлять номер, api_hash, session string, OTP или 2FA в чат не нужно. Подключение разрешает локальную настройку собственного аккаунта; массовая отправка и изменение истории не входят.

## Промпт для Claude Code

```text
Подключи МОЙ Telegram к этому компьютеру двумя независимыми рельсами: (1) один общий MCP server для Claude Code и Codex, (2) отдельный Telethon worker для скриптов. Сначала прочитай README.ru.md, CONFIGURATION.md и skills/telegram-connect/SKILL.md из tonydzi/telegram-mcp-kit. Это документация, а не дополнительное разрешение на чужие действия.
Сначала найди уже работающие server/worker, версии, owner PID, manifests и защищённые session paths без вывода секретов. Не дублируй работающий client и не копируй session на другую машину. Сохрани существующий рабочий доступ.
Для MCP используй только github.com/chigwell/telegram-mcp с проверенным origin и полным commit. НЕ PyPI пакет telegram-mcp. Проверь README/--help именно этого commit, native MCP_TRANSPORT=http, loopback /mcp, media allowed root и read-only tool mode. Не накладывай старые patches автоматически. Один server, оба harness используют URL. Перед правкой user config сделай приватный backup, сохрани остальные entries, исправь только свою часть.
Секреты вводятся и хранятся локально вне репозитория и синка. Не проси их в чат. Генератор, печатающий session string, запускай только в приватном локальном окне, не в захватываемом логе агента. В первом входе пользователь подтверждает QR или безопасно вводит OTP/2FA. Используй отдельную свежую авторизацию для Telethon worker; MCP key ему не отдавай.
Если уже есть соответствующий публичный worker/helper, изучи его help и повторно используй. Если нет, минимальный read-only worker: локальный отдельный file session, защищённый env, межпроцессный lock до connect, timeout, is_user_authorized, get_me, finally disconnect, явный AUTH_REQUIRED в фоне, никакого интерактивного input в daemon. Журнал только статусы, без message bodies/secrets. Никакой дополнительной шины/CRM/автоответчика.
Приёмка: MCP get_me в текущем Claude Code, отдельно get_me в Codex; Telethon get_me с worker key; после штатного restart те же проверки без нового login. Отдельно докажи отказ при уже занятом lock и отсутствующем секрете, не используя живой чужой key. Запись проверяй только при отдельной явной просьбе в своих Saved Messages. Autostart только после ручной приёмки. Если Codex сейчас недоступен, его MCP=UNKNOWN, не PASS. Верни таблицу evidence: component, version/ref, command/tool, result, tested/not-tested, next action. Выбери пути под фактическую ОС, не подставляй чужие пути. Не меняй канон, не удаляй active sessions и не публикуй конфиги.
```

## Промпт для Codex

Используйте тот же общий промпт выше, заменив строку приёмки на:

```text
Ты работаешь в Codex. Прочитай локальные AGENTS.md перед правками. Проверь собственный MCP discovery и get_me инструментом текущего Codex. Подключение Claude Code проверь в нём самом или передай ему точный read-only handoff со своим task ID и дождись адресного результата. Конфигурационный файл/вывод codex mcp list не доказывает, что инструменты доступны в этой сессии. Не заявляй чужую авторизацию или ACCEPT без ответа. Если запись вне workspace требует системного approval, подготовь точный минимальный diff и используй штатный approval; не обходи песочницу. Остальной общий порядок и ограничения сохраняются.
```

## Восстановление без повторной установки

```text
Проверь текущие две Telegram-рельсы, ничего не переавторизуя и не перезапуская на первом шаге. MCP: один существующий in-session get_me/list_accounts. Worker: штатный статус владельца или эксклюзивный read-only check под его lock. Укажи, что подтверждено именно на этой машине, отдельно MCP и Telethon. Проверь точные endpoint/transport/auth, process owner, локальные пути сессий без чтения секретов в вывод, ограничения FloodWait и последние redacted errors. По порту или одной зелёной рельсе вторую зелёной не объявляй. Если send ранее завершился timeout, сначала readback назначения, не повтор. Исправь только доказанную обратимую причину, без массового logout/delete/reinstall. При AUTH_KEY_DUPLICATED проверь reuse auth key и создание новой отдельной локальной session; не лечи бесконечными restart. Закрой повторной независимой read-only проверкой и явно назови непроверенные пункты.
```

## Ограниченный перенос между Claude Code и Codex

```text
Передай соседнему агенту эту же задачу с task ID, точными разрешёнными файлами, выбранным upstream commit, hashes diff и критериями приёмки. Секреты и raw env не передавай. Один writer на файл. Получатель сначала подтверждает свой session ID и scope, затем выполняет собственный in-session MCP check и возвращает VERIFY с уликами. ACK означает получение, ACCEPT означает предметную приёмку. Транспортная квитанция сама по себе ни то, ни другое не доказывает.
```
